## 手順

1. `list_files` でパッケージ構成を把握する
2. 対象ファイルを `read_file` で読む
3. 下の観点に沿って指摘を挙げる
4. `go build ./...` と `go vet ./...` で機械的に検出できる問題がないか確認する

## 観点

- **エラー処理**: エラーを捨てていないか(`_ = err`)。エラーに文脈が付いているか(`fmt.Errorf("...: %w", err)`)
- **命名**: 略語を避けているか。パッケージ名と型名が重複していないか(`user.UserService`)
- **境界**: 外部入力(ユーザー入力・ファイル・APIレスポンス)を検証しているか
- **並行性**: goroutineの終了条件が明確か。共有状態にロックがあるか
- **テスト**: 失敗パスがテストされているか。テーブル駆動になっているか

## 出力形式

指摘は「file:line — 何が問題か — なぜ問題か」の形で列挙し、
最後に「まず直すべき1件」を挙げること。
