# step 08: MCPクライアント — ツールのプラグイン機構

ここまでのツール(read_file、bash、task……)はすべて、エージェントと一緒にコンパイルされる組み込みツールでした。新しいツールが欲しければ、Goを書いて再ビルドするしかありません。

MCP(Model Context Protocol)はこれを解決する標準プロトコルです。ツールを**外部プロセス**として提供し、エージェントは設定ファイル1行でそれを接続する。他人が作ったツールが、再ビルドなしで手に入ります。ツールのプラグイン機構と言ってよいでしょう。

このstepでは、MCPの stdio transport クライアントを実装します。

## この章で学ぶこと

- stdio transport の仕組み(子プロセス + 改行区切りJSON-RPC 2.0)
- initialize → tools/list → tools/call というプロトコルの流れ
- **外部プロセスと話すことの難しさ**——応答しない・死なない・ずれる、への備え
- 設定ファイルは実行権限そのものである、という事実(信頼確認)

## プロトコルは素朴である

stdio transport の仕組みはこれだけです。

1. サーバーを子プロセスとして起動する
2. 標準入出力を通じて、改行区切りのJSON-RPC 2.0メッセージを交換する

使うメソッドも3つだけ。`initialize`(ハンドシェイク)→ `tools/list`(ツール一覧の取得)→ `tools/call`(実行)。[mcp/tool.go](mcp/tool.go) のアダプタを見ると、取得したツールが `tools.Tool` インターフェースに包まれてエージェントに渡ることが分かります。エージェント本体から見れば組み込みツールもMCPツールも区別がありません。step 02で切ったインターフェースに、外部ツールがそのまま差し込める——インターフェース設計の効能の実例です。

ツール名は `mcp__サーバー名__ツール名` という形式に変換します。複数のサーバーが同名のツールを提供しても衝突しないための名前空間です。

## 難しさはプロトコルではなく「相手」にある

素朴なぶん、相手が「他人の書いたプロセス」であることの難しさはこちらが引き受けます。[mcp/client.go](mcp/client.go) の分量の多くは、この備えです。

**応答が返ってこない。** ブロックしている `Read` は context のキャンセルでは中断できません。そこで読み取りは別ゴルーチンに任せ、こちらは channel と `ctx.Done()` を select します(GoでブロッキングI/Oに期限を付ける定石)。応答待ちには必ず上限を置きます。これがないと、応答しないサーバー1つで「Enterを押したら二度とプロンプトが返ってこない」という最悪の壊れ方をします。

**応答がずれる。** サーバーは通知(IDなしのメッセージ)を勝手に送ってきますし、タイムアウトで諦めたリクエストへの応答が後から届くこともあります。「次に来た1行」を答えとみなす実装だと、一度タイムアウトしただけで以降ずっと1つずつずれた応答を読み続けます。対策はリクエストIDとの突き合わせです。自分宛てでないものは読み飛ばす。

**終了しない。** stdinを閉じてもプロセスが残ることがあります。`Close` は停止を一定時間待ち、だめなら強制終了します(実装済み。テストは実プロセスで検証しています)。

**エラーを標準エラーにだけ吐く。** サーバーのstderrを捨てると「なぜか繋がらない」だけが残ります。どのサーバーの出力か分かる接頭辞を付けて転送します(実装済み)。

## 設定ファイルは実行権限そのものである

`.mcp.json` に書かれた `command` は、エージェントの**起動と同時に子プロセスとして実行**されます。つまり悪意あるリポジトリは、`.mcp.json` に1行書いておくだけで、cloneした人がエージェントを起動した瞬間に任意のコマンドを走らせられます。

そこで [main.go](main.go) の `confirmTrust` は、起動時に「このディレクトリの設定は何を実行しようとしているか」を一覧表示し、信頼するかを1度だけ確認します。一覧には bash の allowlist も含めます——「確認なしで実行してよい」の宣言は、承認フローに穴をあらかじめ開けておくことに等しいからです。拒否されたら起動を中止します。確認が取れない(標準入力が繋がっていない)場合も中止です。「聞けなかったから通す」は安全機構としてありえません。

## 検証

```bash
make check STEP=08
```

テストは `io.Pipe` で繋いだ疑似サーバー相手にプロトコルを検証します。`TestCallSkipsNotifications`(通知と別ID応答の読み飛ばし)、`TestCallTimesOutOnSilentServer`(沈黙するサーバー)、`TestLateResponseDoesNotDesyncNextCall`(遅延応答によるズレ)がこのstepの主題です。

## 動かしてみよう(任意)

```bash
export ANTHROPIC_API_KEY=sk-ant-...
cd example
go run ../steps/08-mcp
```

起動すると信頼確認が表示されます。`example/.mcp.json` のサーバー定義は空ですが、`.agent/settings.json` の allowlist が「承認なしで実行を許可」の宣言として一覧に載るためです。`n` と答えると起動が中止されることも確かめてください。

手元にMCPサーバーがあれば(npxで動く公開サーバーでも自作の数十行のサーバーでも)、`.mcp.json` に `{"mcpServers": {"名前": {"command": "...", "args": [...]}}}` と書くだけで、そのツールがエージェントに生えます。信頼確認の一覧にコマンドが現れることも確認してください。
