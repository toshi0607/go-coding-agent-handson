# step 10: 仕上げ — ストリーミングとhooks

最後のstepです。機能はすでに出揃っているので、ここで足すのは**体験**と**拡張点**です。

1つ目はストリーミング。ここまでのエージェントは、LLMの応答が全部生成し終わってから一気に表示していました。長い応答では数十秒の沈黙が続きます。生成されたそばからテキストを流すように変えます。

2つ目はhooks。ツール実行の前後に、ユーザーが定義した外部コマンドを差し込める拡張点です。エージェント本体を変更せずに、検査やログ記録を追加できるようにします。

このstepの解答を埋めると、エージェントは [final/](../../final/) と同じ完成形になります。

## この章で学ぶこと

- SSEイベントの列から完全なレスポンスを組み立て直すこと(蓄積と表示の役割分担)
- プロンプト(お願い)と拡張点(確実に実行される)の使い分け
- fail-closed——安全機構は「壊れたら止まる」が正しい

## ストリーミング: 蓄積と表示は別物

ストリーミングでは、レスポンスがSSEイベントの列に分解されて届きます。

```
message_start → content_block_start → content_block_delta ... → message_stop
```

実装の鍵は**役割分担**です。画面に流すのはテキスト差分(text_delta)だけですが、会話履歴に積むのは**完全なレスポンス**でなければなりません。tool_use ブロックの引数も、細切れのJSON断片(input_json_delta)として届きます——これを画面に流しても意味不明なだけです。

そこで `Stream` は2つの仕事を並行して行います。すべてのイベントをSDKの `Message.Accumulate` で完全なメッセージに組み立て直しながら、text_delta だけを `onText` コールバックに流す。戻り値の完全なメッセージを履歴に積むのはエージェントループの仕事で、`onText` はあくまで表示用です。

`llm.Client` をインターフェースにしておいた効能がここでも出ます。`ReplayClient` にも `Stream` を実装してあります(全文を一度に `onText` へ流すだけ)が、エージェントループのテストは何も変わらずに通ります。

## hooks: プロンプトとの決定的な違い

「危険なコマンドを実行しないで」とシステムプロンプトに書くことはできます。しかしプロンプトはLLMへの**お願い**であり、忘れられることがあります。hooksは違います。プログラムとして**100%実行されます**。この確実性の違いが、プロンプトと拡張点の使い分けの軸です。

イベントは2種類です。

- **PreToolUse**: ツール実行の直前。終了コード2で実行をブロックできる(stderrがLLMへのフィードバックになる)
- **PostToolUse**: ツール実行の直後。ログ記録やフォーマッタ実行などに使う(結果には介入できず、失敗しても無視される)

hookコマンドには、実行内容(ツール名・入力)がJSONで標準入力から渡されます。`jq` などで検査するスクリプトが数行で書けます。[example/.agent/settings.json](../../example/.agent/settings.json) には `rm` による削除をブロックする実例があります。

`executeTool`(実装済み)での差し込み順にも意味があります: PreToolUseフック → 権限チェック → 実行 → 切り詰め → PostToolUseフック。機械的な検査(フック)が先、人間の判断(承認)が後です。機械で弾けるものを人間に確認させるのは、step 04 で学んだ確認疲れの原因になります。

## fail-closed: 壊れたら止まる

課題の核心はここです。PreToolUseフックの契約は「exit 0 = 許可 / exit 2 = ブロック」の2つだけ。では、それ以外——フックの起動失敗、タイムアウトによるkill、スクリプトのバグによる exit 1——をどう扱うべきでしょうか。

「判定できなかったのだから通す」(fail-open)を選ぶと、**フックが壊れた瞬間に防御が黙って無効化されます**。ユーザーは守られているつもりで、守られていません。安全機構は「壊れたら止まる」(fail-closed)が正しい。契約外の結果はすべて「検査が完了していない」とみなしてブロックします。

これは final/ のレビューで High 判定を受けて直した箇所でもあります。最初の実装は「exit 2 以外は通す」でした。安全機構を書くときは、正常系ではなく**壊れ方**から設計する必要があります。
